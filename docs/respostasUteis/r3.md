# R3 · Por que o Deep Analysis precisava de bootstrap e suporte metodológico lado a lado

**Data:** 2026-09-04 · **Contexto:** [DEC-081](../automation/07-log-de-execucao.md) — implementação de M3.3, painel `MethodologicalSupport` no modal Deep Analysis.

> Esta série guarda respostas de cunho **metodológico e conceitual** — o raciocínio, não o passo a passo. O registro operacional fica no [log de execução](../automation/07-log-de-execucao.md); aqui fica o **porquê**.

---

## 1. O que já existia e o que faltava

- **Bootstrap** (`/branch-support`, M3.1/DEC-070): mede robustez **amostral** — reamostra os dados, método de inferência fixo. Já estava na UI.
- **Suporte metodológico** (`sup(b) = |pipelines que recuperam b| / M`): mede robustez **metodológica** — dados fixos, varia o alinhador/inferência. Isso só existia dentro de scripts de CLI (`resultado_principal.py`, `audit_variola.py`), **hardcoded para Variola**, sem nenhuma rota de API — não dava pra ver isso pra nenhum outro projeto, nem na interface.

As duas métricas são **ortogonais por construção** (uma varia o dado, a outra varia o método) — e é exatamente essa ortogonalidade que sustenta a afirmação (i) do artigo (`docs/science/scripts/resultado_principal.py`): *"UFBoot máximo não garante robustez metodológica"*. Sem a segunda métrica lado a lado com a primeira, a interface não conseguia mostrar essa afirmação em nenhum clado individual — só o script de linha de comando conseguia, e só para Variola.

## 2. O que o DEC-081 fechou

1. Rota nova `GET /api/tree/{project}/methodological-support?alinhador=` (`Backend/src/suporte_metodologico.py`) — reusa `StabilityAnalyzer.clade_records()`, a mesma classe já validada por oráculo dendropy (1682 testes/0 divergências, DEC-069). Não precisou de oráculo novo: é reuso direto, não reimplementação.
2. `Frontend/phylotreeminer/src/components/analysis/MethodologicalSupport.jsx` junta bootstrap e suporte metodológico **pelo mesmo `clade_id`** (bipartição canônica D3/D5), dentro do universo de cada alinhador — sem normalizar ou misturar as duas grandezas.
3. Marca com a tag **"discordante"** todo ramo onde `bootstrap ≥ limiar_alto` e `suporte_metodológico < 1.0` — materializa visualmente, ramo a ramo, o caso que viola a leitura ingênua de "bootstrap alto = árvore confiável".

## 3. Valor agregado ao Deep Analysis

Antes: quem olhasse o Deep Analysis via só o bootstrap alto e podia concluir (erroneamente) que o clado era robusto.

Depois: no projeto `Variola_VARV52_reexec_20260903`, a tabela expõe **288 ramos com bootstrap, dos quais 40 têm bootstrap alto sem unanimidade metodológica.**
